# D2: измерения и сценарий защиты, 28.09.2026

Текущая реализация: ветка database, основа c1c30c8 плюс незакоммиченные изменения D2. Java 21.0.10, Windows 11, отдельная PostgreSQL 18.3 на порту 55440. Проверялся отдельный экземпляр; Docker-система команды на 5173 не проверялась. Docker Compose использует PostgreSQL 16, поэтому после объединения нужно повторить демонстрацию на ПК команды.

## Измеренное сравнение

Результаты записаны тестом `D2DatabaseIntegrationTest.exportsReproducibleComparisonWithoutClaimingUnmeasuredBusinessBenefit`. EDD и CP-SAT получают один и тот же неизменяемый вход внутри каждого набора: одни поезда, горизонт, рейсы, ресурсы и обязательства. Seed 42, time limit 10 секунд. Данные модельные; численные нормы циклов из кейса. EDD — последовательный базовый алгоритм по срокам, CP-SAT — решатель ограничений.

Сохранённая машинная версия: [D2_comparison_2026-09-28.json](../database/reports/D2_comparison_2026-09-28.json). Она включает sourceSnapshotId, полный исходный SHA-256, hash результата, версии, pending-рубежи и времена. Измерения ниже относятся именно к этому запуску.

В нормальном наборе оба алгоритма дают одинаковое качество по измеренному makespan. Оснований заявлять процент улучшения, экономию или прирост готовности нет. Время одного запуска с прогревом JVM не является сравнительным бенчмарком скорости.

В BLOCKED6 путь доступен только первые сутки. EDD не нашёл план, но не доказал невозможность; CP-SAT доказал несовместимость ограничений именно этой E2-модели. Для обоих результатов согласование запрещено, показатели проверенного плана отсутствуют (`metrics=null`). Ноль размещённых работ здесь не означает нулевую потребность: независимая потребность остаётся 12.

## Что проверено

- Полный `mvn verify`: 80 тестов в 15 наборах, 0 ошибок, 0 падений, 0 пропусков. Включены DB-интеграция, нативный CP-SAT, независимые проверки источника и отрицательные примеры E3.
- `npm run build`: TypeScript и production-сборка Vite прошли.
- Браузер на отдельном API 18080 / UI 15173: E2_6 показывает PASS / E2_MODEL, 12/12 работ, 36 составо-часов, 0 конфликтов; согласование переводит план в APPROVED версии 1. BLOCKED6 показывает INFEASIBLE / FAILED, кнопка согласования недоступна, метрики успешного плана не выводятся.
- API: нормальный E2 получает PASS и утверждается; неподходящий результат получает 422. Изменённые интервалы, удалённая работа, неверный hash или версия не могут использовать предыдущий PASS.
- Ошибка общего происхождения: намеренно удалены работы одного состава и из входа солвера, и из результата. CP-SAT решает неполную задачу успешно, D2 восстанавливает недостающее по исходному payload и блокирует утверждение.
- Отдельные проверки E3 выявляют уборку после четвёртого рейса, дефицит резерва по городу, изменение frozen, неправильный порядок выпуска, конфликт подготовки, неправильный город станка, календарный срок, потерю второго состава пары и превышение пяти ТО. Пока это отдельные модули с явными входными правилами, не runtime-проверка FULL43.

## Демонстрация на 60–90 секунд

1. Выбрать «6 составов · 252 рейса», загрузить и рассчитать. Показать разные начальные пробеги, исходный hash и календарь.
2. Показать отдельно OPTIMAL решателя и PASS / E2_MODEL независимой проверки. На экране: 12/12 работ, 0 конфликтов, 36 составо-часов. Допустимо согласовать модельный план; фактический статус поездов не меняется.
3. Выбрать недоступный путь, пересчитать: INFEASIBLE и FAILED. Показать объяснение и недоступное согласование. Подчеркнуть, что система сообщает о дефиците ресурса, а не рисует допустимый план.
4. На слайде сравнения показать таблицу выше: качество на обычном примере одинаковое, CP-SAT дополнительно доказал невозможность отрицательного примера. Никакой выдуманной экономии.
