# ОКНО ВСМ — инструкция пользователя

Система строит 14-суточный план технического обслуживания (ТО) парка ЭВС360 из 43 составов вокруг фиксированного расписания, принимает изменения через заявки и пересчитывает план. Данные модельные; нормативы ТО IS100–IS700 взяты из кейса.

## Как это устроено

```
Расписание и парк (PostgreSQL) ── версия данных N, контрольная сумма
        │ «Построить план»
        ▼
Поиск замен + CP-SAT            ТО по пробегу и уборки; длинному ТО резерв отдаёт свои рейсы
        │
        ▼
Черновик плана → Парк (календарь, карточки составов)

Заявка планировщика ──► диспетчер: согласовать / отклонить
        │ согласована
        ▼
Версия данных N+1 ──► планировщик «Пересчитать» ──► «Изменения после пересчёта»
```

Заявка ничего не меняет, пока её не согласует диспетчер. Любое изменение данных создаёт новую неизменяемую версию; прежняя остаётся в истории, и план всегда привязан к конкретной версии.

## Запуск

```bash
docker compose up -d --build
```

Открыть http://localhost:5173. После `git pull` обязательно `--build`.

## Роли

| Вход | Роль | Что делает |
|---|---|---|
| `planner` / `planner-demo` | Планировщик | Загружает парк или своё расписание CSV, строит план, отправляет заявки, пересчитывает после ответа |
| `dispatcher` / `disp-demo` | Диспетчер | Согласует или отклоняет заявки, при отказе состава назначает замену из резерва |

Права проверяет сервер. Пояснения к каждому блоку — значок **i** рядом с заголовком.

## Планировщик

**План ТО**
1. «Загрузить парк: 43 состава» — один раз; дальше данные живут на сервере.
2. «Загрузить расписание CSV» — своё расписание: `рейс;состав;отправление;прибытие` (для нового рейса ещё `откуда;куда;км`), время `2031-07-01 06:05` по Москве. Файл из Excel (Windows-1251) тоже подходит. Получается новая версия данных.
3. «Построить план» — 1–2 минуты. Плитки: работ ТО, уборок, рейсов передано резерву, резерв Санкт-Петербурга, решение CP-SAT, проверка интервалов.
4. Если данные изменились после расчёта, появится предупреждение и кнопка «Пересчитать». После пересчёта — таблица «Изменения после пересчёта»: сдвинутые, переданные другому составу, новые и снятые рейсы и работы.

**Заявки → Новая заявка**
- *Изменение рейса*: состав, рейс, новое время (кнопка «+5 мин»), причина.
- *Отказ состава*: рейс текущих суток, время ремонта, что случилось.

После согласования у заявки появляется «нужен пересчёт» и кнопка «Пересчитать».

## Диспетчер

**Заявки** — все заявки со статусами «Ждёт диспетчера», «Согласована», «Отклонена». «Рассмотреть» открывает решение:
- изменение рейса — «Согласовать» (создаётся новая версия данных) или «Отклонить» с причиной;
- отказ состава — «Принять отказ и подобрать замену»: состав снимается с оставшихся рейсов суток, система показывает кандидатов из резерва с обоснованием, «Назначить» согласует замену. Сверху — остаток резерва по городам.

**Парк** — действующий план: поиск по составу или рейсу, рейсы/ТО/уборки, масштаб сутки/неделя/горизонт, карточка состава.

## Сценарий показа (3–4 минуты)

1. planner: «Загрузить парк» → «Построить план» (≈1 мин): 76 ТО, 68 уборок, 30 рейсов передано резерву, решение оптимальное.
2. «Парк»: найти состав, открыть карточку; показать ТО IS520 в окне, которое освободил резерв.
3. «Заявки»: изменение рейса на +5 мин → «Отправить диспетчеру».
4. Во втором окне dispatcher: «Рассмотреть» → «Согласовать». Вторую заявку — «Отклонить» с причиной.
5. planner: «Нужен пересчёт» → «Пересчитать» → «Изменения после пересчёта».
6. planner: отказ состава перед рейсом → dispatcher: «Принять отказ» → назначить замену; резерв города уменьшился.

## Ограничения

- План — черновик: независимая проверка интервалов пройдена, полная проверка D2 для 43 составов в разработке, поэтому утверждение плана отключено.
- Отказы обрабатываются в пределах оперативных суток (первый день горизонта).
- Для длительных ТО используются только резервы того же города; пять составов в депо без подтверждённого выпуска не задействуются.

## Если что-то не так

| Симптом | Что сделать |
|---|---|
| Старый вид интерфейса | `docker compose up -d --build`, обновить страницу (Ctrl+F5) |
| Просит войти снова | После перезапуска API сессия сбрасывается — войти заново |
| «Выберите рейс текущих суток» | Отказ оформляется только для рейсов первого дня, которые ещё не ушли |
| Расчёт идёт дольше 2 минут | Дождаться: поиск замен ограничен 20 шагами, решатель — 60 с на шаг |
